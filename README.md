# 桌宠 DeskPet

一个安卓桌面宠物 App：桌宠**浮在桌面和其他任何 App 之上**，贴边吸附、朝向随位置自动变化。
**四条边都能吸附**：四个角（左上 / 右上 / 左下 / 右下）+ 四条边（上 / 下 / 左 / 右）。

| 项 | 值 |
|---|---|
| 包名 | `com.dsh.deskpet` |
| 最低版本 | Android 8.0（API 26） |
| 目标版本 | **Android 16（API 36）** |
| 针对屏幕 | **1440 × 3168** |
| 依赖 | **纯平台实现**，无 AndroidX / Material |
| 体积 | 约 9.5 MB（其中绝大部分是素材 PNG） |

---

## 一、装到手机上

1. 把 APK 传到手机安装（需要允许「安装未知来源应用」）
2. 首次打开会提示两项权限：
   - **悬浮窗权限**（必须）—— 点卡片里的按钮跳到系统设置开启
   - **通知权限**（建议）—— 前台服务需要它常驻
3. 点 **开启桌宠**，回到桌面就能看到它了

> 桌宠是**前台服务**，通知栏会有一条常驻通知。想关掉就在 App 里点 **关闭桌宠**。

## 二、怎么和它互动

**悬浮状态下只有两种操作** —— 这是刻意的设计，所有设置都只能在 App 界面里改。

| 操作 | 行为 |
|---|---|
| **单击** | 先压扁再弹起。压扁方向**跟着头的朝向**：头朝上就上下压扁、向上弹；头朝左就左右压扁、向左弹。倒挂在顶上时头朝下，于是向**下**弹 —— 弹起方向永远指向屏幕内侧 |
| **拖动** | **1:1 严格跟手**，无阻尼。手指按在哪里，素材中心点就在哪里 |
| **松手** | 吸附到最近的边，带位置补间 + 小回弹 |

## 三、分区与朝向

屏幕**左右各半分**共用同一套规则；纵向则**不看上下半屏**，只看离上沿有多远：

| 轴 | 判定基准 | 距离 |
|---|---|---|
| 纵向 | **离上沿 ≤ 240px** 就用上沿（倒挂），否则一律用下沿 | `dv` = 足迹到基准边的距离 |
| 横向 | **本侧吸附边**：左半屏量左边，右半屏量右边 | `dr` = 足迹到该边的距离 |

| 区 | 范围 | 松手后 | 素材 | 朝向 |
|---|---|---|---|---|
| **A** | `dv ≤ 365` 且 `dr ≤ 200` | 吸附**最近的角**（四个角之一） | 角落素材 | 正立（上边带内则倒挂） |
| **B** | 中心点越过分界线 | 水平贴侧边 | 正立素材 | **旋转 90°，头朝屏幕内侧** |
| **E** | 其余全部 | 贴**更近的那条边**（上下左右四选一） | 正立素材 | 贴侧边则旋转；贴上沿倒挂，贴下沿正立 |

> 原本的 **C 区（贴底边带）已合并进 E 区**，与 E 完全同一套逻辑。
> 在屏幕底部附近，E 的"贴更近的边"自然就是贴底边，所以观感不变；
> 但靠近底部**又**靠近侧边时会正确地贴侧边并旋转，不再被 C 强行拉到底边。

### 上边带：只有离上沿 240px 以内才倒挂

用户规定：**屏幕上沿起 240px 以内人物头朝下**（上角 / 贴上沿），
**上方其余区域跟下边完全一致** —— 也就是说不看"上半屏"。
240px 以外贴着左右侧边时，就是普通的**侧边旋转区**（躺倒），跟下半屏一样。

| | 下边组 | 上边组（离上沿 ≤ 240px） |
|---|---|---|
| 角落 | `CORNER_BR` / `CORNER_BL` | `CORNER_TR` / `CORNER_TL` |
| 贴水平边 | `BORDER_R_UPRIGHT` / `BORDER_L_UPRIGHT` | `EDGE_TOP_R` / `EDGE_TOP_L` |
| 素材 | 原样 | **上下翻转**（flipV） |
| 收起 | 向**下**滑出屏幕 | 向**上**滑出屏幕 |
| 呼出 | 从**下方**滑入 | 从**上方**滑入 |
| 点击弹起 | 向**上**弹（头朝上，朝屏幕内侧） | 向**下**弹（倒挂，头朝下，同样朝屏幕内侧） |

带内的形态就是下边沿**水平轴**镜像过来的：贴在底边是"站在地上"，
贴在上沿就是"倒挂在顶上"。左侧同理（水平镜像 + 上下翻转 = 旋转 180°）。
**侧边旋转区（旋转 90° 躺倒）永不翻转** —— 否则头会朝错方向。

带边界有 **24px 单向滞回**：带内（≤ 240）**一定**倒挂（用户的规则是几何的），
退组则要越出 240 + 24 才生效，避免手指停在边界上时素材翻来翻去。
`TOP_BAND_PX` 是**屏幕坐标里的固定像素**，与宠物大小、与 A 区尺寸都无关。

### 垂直基准是显式枚举（`VERT_*`）

`PetState` 里用 `VERT_NONE / VERT_BOTTOM / VERT_TOP` 把"以哪条水平边为准"**显式建模**，
分区（`zoneOf` / `zoneWithHysteresis`）与吸附（`snapEdgesForZone` / `snapPosition` /
`stateForZone`）全部**显式接受**这个枚举。

> **踩过的坑**：加"上边吸附"时曾图省事，直接把 `bottomDist` 换成
> `min(topDist, bottomDist)` 就完事 —— 但 `zoneOf / snapEdgesForZone / snapPosition`
> 的语义全都建立在"**到基准边的距离**"上，悄悄换掉距离的含义却不同步改判定规则，
> 于是"上边/上角吸不上、初始位置变了、侧边头部朝向错了"一起爆发，只能回滚。
> 现在基准单独建模：`vertOf` 只负责**选边**，`vertDistFor` 只负责**量距离**，
> 任何一处漏传基准，编译器立刻报错。

其余要点：

- **B/E 分界线用「素材中心点」判定**，不是边缘。门槛是 `200 + 半个足迹宽`，
  这样"完全贴边静止"能稳定落在 B 内，不会在旋转/正立之间反复横跳。
- 门槛里的半宽取 `max(足迹宽, 足迹高)` —— 与朝向**无关**。
  若用随朝向互换的那个值，会形成「门槛决定朝向、朝向又决定门槛」的**自反馈振荡**。
- 分界线附近有 **14px 滞回死区**，把手指抖动吸收掉。
- **朝向由"最终贴到哪条边"决定**：只要贴侧边就一定旋转，即使拖动过程中没转过。
- 松手时**边转边靠**：旋转 180ms、位移 220ms，所以到边之前就转正了。
- **素材翻转必须是"状态的纯函数"**（`isLeft(state)` / `flipVFor(state)`）：
  位图缓存、素材中心点缓存都以状态为键，翻转一旦取决于"当前离上沿近不近"
  这类运行时标志，缓存就会串味 —— 中心点算错（位置自己变）、命中判定与实际画面不一致。

### 左右镜像

左侧不单独出图，渲染时对右侧素材做**水平镜像**。远处实测确认
`flip(mirror(右下角)) == 左下角`（像素差异 0.00），所以素材目录只保留右侧两份。

贴着右边框时旋转 **−90°**（头朝左），左边框 **+90°**（头朝右）。

### 旋转永远走最小角度

用户要求："需要旋转的时候无论方向旋转最小角度"。

| 切换 | 转多少 | 怎么转 |
|---|---|---|
| 正立 `↔` 贴右边框 | **−90° / +90°** | 头从"上"扫向"左 / 右"，一步到位 |
| 正立 `↔` 贴左边框 | **+90° / −90°** | 同上，方向相反 |
| **贴右边框 `↔` 贴左边框** | **0°** | **不转**，只换图（见下） |
| 旋转角相同的状态之间 | 0° | 只换素材 / 镜像，本来就不用转 |

最后一行的道理：`rotate(+90) ∘ mirror ≡ mirror ∘ rotate(-90)`，
所以**贴左边框画出来的东西正好是贴右边框的水平镜像** ——
左右互切时换图本身就是镜像，硬转 180° 只会让人物先立正再倒下、白转一大圈。
这一下交给镜像翻转动画（[左右镜像](#左右镜像)那个卡片翻转）即可，观感也小得多。

实现上 `startRotAnim` 把角度差**规约到 (−180, 180]**（所以永远不会绕远路转 270°），
差值正好 180° 时判定为"左右互换"，直接对齐角度、不播旋转。

## 四、窗口策略（关键设计）

悬浮窗**只有宠物那么大**（外加容纳旋转与轻跳的余量），**不是整屏**。

这是"不遮挡屏幕"的根本保证：窗口之外的触摸由 Android 直接派发给桌面/其他 App，
我们连事件都收不到，不依赖任何 flag 技巧。窗口内部再做**逐像素 alpha 命中判定**，
素材透明处照样放过。

> **踩过的坑**：曾用整屏窗口 + `FLAG_NOT_TOUCH_MODAL`。而该 flag 的语义是
> "本窗口之外的触摸由我自己处理"，结果整个屏幕都点不动。

### 绝不裁切

窗口取**旋转包络**：`max(对角线, 宽×1.22, 高×1.22)`。

- W×H 矩形绕中心转 θ 时外接框是 `W|cosθ| + H|sinθ|`，45° 附近约等于**对角线**，
  比 `max(W,H)` 大得多 —— 用 max 会在中间角度切掉。
- `×1.22` 是给点击压缩留的（压缩会把横向撑大 22%）。
- 上下余量都按素材高度**等比**给（`高 × 8% + 8`），不能用固定像素，否则放大后会切顶。
  两头必须**一样大**：贴底时向上弹、贴上沿时向下弹，弹起方向永远朝屏幕内侧；
  而且余量必须**与状态无关** —— 否则上下两组形态的窗口高度不同，进出上边带时
  窗口会 resize，看起来就是跳一下（与"窗口取两套素材并集"是同一个道理）。

### 旋转支点在素材中心

不用"手指作用点"当支点：绕中心转时素材离中心最远就是半对角线，对角线大小的窗口恰好够用；
绕偏心点（尤其按在角上）转时最远可达 1.5×对角线，窗口要开到约 3×对角线（≈2100px，
几乎满屏宽），会重新引入"挡住触摸"的问题。两者不可兼得，服从"不裁切"。

### 位置的保存：只认"落点"，不认"这一帧在哪"

`PetView` 里有两个位置概念，**绝不能混用**：

| | 含义 | 什么时候会跑偏 |
|---|---|---|
| `anchorX/anchorY` | 当前这一帧画在哪 | 回弹补间途中在**过冲点**上；收起/呼出动画里已经**滑到屏幕外** |
| `restCenterX/restCenterY` | 最终会停在哪（落点） | —— 由吸附/落位/滑入时 `markRest()` 维护 |

保存位置、以及"收起被打断要滑回哪里"一律用**落点**。
以前这几处用的是当时的 `anchor`，于是连点时会存下中间态，位置就变了
（用户反馈："多次快速点击收起/呼入位置会发生变化"）：

1. 拖动后 400ms 的延迟落盘撞上回弹补间 → 存的是过冲点附近（默认幅度下差 ~4px，
   幅度调大后差得更多）；
2. 收起滑完 `removePet()` 又存一次 → 那时 anchor 已在屏幕外，只能靠夹取兜底；
3. 连点时的"滑回哪里"，是在开始滑出那一刻按当时 anchor 现记的 → 正在回弹时记下的也是过冲点。

现在这三条路径全部读同一个落点，且 `restoreRest()` 只要 `markRest()` 过就一定成功，
不会再退回 `applySnap()`（那个会按状态重排到"标准位置"，例如侧边形态直接跳到垂直居中）。
实机验证：拖动后 prefs 与真实足迹的偏差从 4~7px 降到 ≤1px，十二连点后位置逐像素不变。

> ⚠️ **服务层的兜底也不许用 `applySnap()`**：贴右边框的"标准位置"是右边框**底部**
> （`isZoneless(BORDER_R)` 为 false，走的是贴底分支），所以一旦兜底走到它，
> 宠物就会**瞬移到右下角** —— 用户反馈的正是这个。现在兜底是 `stayVisible()`
> （只把越界锚点夹回屏幕，不重排）。

### 点一下不能打断吸附补间

吸附补间一共约 **0.6 秒**（位移 220ms + 回弹 360ms）。这期间按一下宠物，
`ACTION_DOWN` 会取消补间（"抓住了就停住"是对的）—— 但如果只是**点一下**（没拖动），
补间就再也没人补完：宠物停在半路，于是要么跟屏幕边缘留一条缝、
要么越界半张脸卡在边上。实测：松手后 200ms 点一下，宠物会停在**越界 23px** 的位置。

现在按下的那一刻先把**落点**记进 `pendingSnap`，松手时若是"点"（`dragging == false`）
就 `resumePendingSnap()` 把补间补完；真拖动了则以拖动为准，丢掉这个落点。

> 边界：只在"点一下"时补完。若用户按住不放（手指还没抬起），宠物就停在半路 ——
> 这是刻意的"抓住了"手感；拖动松手会重新吸附，同样不会留缝。

## 五、动画参数

| 参数 | 值 | 作用 |
|---|---|---|
| `SNAP_MS` | 220ms | 松手吸附的位置补间 |
| `ROT_MS` | 180ms | 旋转（拖动中 / 松手贴边前） |
| `FLIP_MS` | 260ms | 镜像翻转（左右，跨屏幕中线）与**上下翻转**（进出上边带）|
| `HOP_MS` | 380ms | 单击的压扁 + 弹起 |
| `SQ_MAX` | 0.22 | 点击压缩最大比例 |
| 回弹幅度 | 36px × 倍率 | 松手吸附的过冲量，可调 |
| 回弹时长 | 360ms × 倍率 | 回落时长，可调 |

动画帧走 **Choreographer（vsync 对齐）**，不用 `postDelayed(16)` 自走循环。

两个翻转动画都不是"改尺寸"，而是**画布上的压扁**：素材在状态切换那一帧就换好了，
动画只是把 180° 的观感做出来（中途压成一条线再展开）。所以它们不参与任何
尺寸/位置记账，也就不会把宠物挪走。

### 松手回弹

| 松手瞬间 | 弹的方向 |
|---|---|
| 素材**没超出**屏幕 | 先向**屏幕外**弹，再回到贴边位置 |
| 素材**已超出**屏幕 | 先向**屏幕内**弹，再回到贴边位置 |

这两条其实是同一件事：**过冲方向 = 吸附的移动方向**。因为"已超出"恰好等价于
"吸附会往回拉"，所以直接用 `sign(目标 − 当前位置)` 即可。

实现是两段式补间：先冲到 `贴边位 + 方向×幅度`，再平滑回落。只在吸附的那条轴上过冲。
上下两边共用这一套判定与夹取规则，所以"往上冲"与"往下冲"允许的幅度完全一样。

## 六、App 界面

从上到下：

1. **切换形象** —— 列出 `assets/pet/` 下所有角色（5 个：《孤独摇滚》）
2. **权限** —— 悬浮窗 / 通知
3. **开关** —— 开启 / 关闭桌宠
4. **外观** —— 大小滑块（屏幕可用高度的 **6%~40%**，默认 **8%**）、开机自启
5. **松手回弹** —— 幅度倍率与时长倍率，各带**滑块 + 数字输入**，范围 **0.1 ~ 10**
   （1.0 = 36px / 360ms）。滑块用**对数刻度**，1.0 正好在中间。
6. 提示

> 回弹参数在**每次吸附时现读**，改完立刻生效，不用重启桌宠，也不会挪动它的位置。
> 大小以**吸附边为基准**缩放：贴底/角落则底边不动（否则缩小后浮空），
> 贴侧边则吸附那侧不动（否则放大后超出屏幕）。

## 九、代码结构

| 文件 | 职责 |
|---|---|
| `PetState.kt` | 纯逻辑：垂直基准（`VERT_*`）、分区判定、吸附位置、旋转角、翻转、缩放。**无 Android 依赖，全部可单测** |
| `PetView.kt` | 悬浮窗本体：绘制、触摸、动画、窗口摆放 |
| `PetSprite.kt` | 素材加载、镜像/翻转、按状态缓存位图 |
| `PetService.kt` | 前台服务：挂载/移除悬浮窗、屏幕开关、窗口布局 |
| `Prefs.kt` | SharedPreferences 封装（含默认值迁移） |
| `MainActivity.kt` | 控制面板 |

坐标语义有一个**关键约定**：`PetView` 里的 `anchorX/anchorY` 是**素材中心点**的屏幕坐标，
不是格子左上角。足迹盒的位置由中心点反推。改这块时务必留意，
历史上多个"抽搐/平移"的 bug 都源于这里语义不一致。

状态编号（`Prefs.snap_state` 持久化，**只能新增，不能改动已有编号**）：

| 编号 | 状态 | 位置 | 素材 |
|---|---|---|---|
| 0 / 1 | `CORNER_BR` / `CORNER_BL` | 下角 | 角落素材，正立 |
| 2 / 3 | `BORDER_R` / `BORDER_L` | 侧边（垂直自由） | 正立素材，旋转 ∓90° |
| 5 / 6 | `BORDER_R_UPRIGHT` / `BORDER_L_UPRIGHT` | 贴下沿 | 正立素材 |
| 7 / 8 | `CORNER_TR` / `CORNER_TL` | 上角 | 角落素材，**上下翻转** |

## 十、实机验证小工具

`tools/` 下几个脚本记录了"怎么在这台模拟器上把行为测出来"（避开踩过的坑）：

| 脚本 | 用途 |
|---|---|
| `tools/petcheck.ps1` | 读 `deskpet.xml` 看 `snap_state / pos_left / pos_top`；用 `input motionevent` 造拖动（`input swipe` 的结果无法判读） |
| `tools/verify_top.ps1` | 拖到九个吸附位并逐条读回状态；起手点由**窗口 frame** 反算（prefs 里的坐标可能被 restore 夹取过，未必是当前值） |
| `tools/verify_slide.ps1` | 收起/呼出方向：轮询悬浮窗 frame，看 y 是往哪边跑 |
| `tools/crop.py` | 裁图放大，肉眼核对素材朝向 |

两个必须注意的坑：

- **贴上沿时不要按素材中心点起手**：中心点（y≈130）落在状态栏上，触摸被状态栏吃掉，
  表现为"下拉通知栏"而宠物一动不动。改按足迹下缘往上 20px 处。
- 截图**不能**用 `adb exec-out screencap -p > file`（PowerShell 会把二进制转成 UTF-16，
  PNG 损坏），要走"设备内落盘 + `adb pull`"。`.ps1` 脚本一律存成 **UTF-8 带 BOM**，
  否则 GBK 代码页下中文注释会被读坏、脚本直接语法错误。
